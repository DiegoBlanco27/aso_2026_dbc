# Practica 2: Conexion SSH
- Desde nuestro equipo local vamos a conectarnos remotamente a un servidor Ubuntu usando el metodo SSH, desde el nos conectaremos a otros dos servidores Ubuntu
  
## Entorno Virtualizado
Usaremos las siguientes maquinas virtuales:
- Ubuntu Server 26.04 LTS, se llamara SERVER-A, tendra un adaptador puente y dos redes internas "intnet 1" y " intnet 2"
- Ubuntu Server 26.04 LTS, se llamara SERVER-B, tendra una red interna "intnet 1"
- Ubuntu Server 26.04 LTS, se llamara SERVER-C, tendra una red interna "intnet 2"

- El equipo SERVER-A tendra un usuario con mi nombre "diego"
- Los equipos SERVER-B y SERVER-C tendran cada uno un usuario llamado "sysadmin"

## Conexion a SERVER-A
Primero nos aseguraremos de que el servicio de ssh este instalado, para ello buscaremos los archivos de configuracion SSH con el comando ```ls /etc/ssh``` sino estan los archivos, lo instalaremos con el comando ```sudo apt install openssh-server```

Lo primero de todo, crearemos una clave publica con el comando ```ssh-keygen``` para poder conectarnos de forma transparente, añadiendole ```-b 1024``` le establecemos una longitud maxima.

Ahora, ejecutaremos ```cd ~/.ssh``` para dirigirnos a la carpeta ssh , tenemos que pasarle la clave publica de nuestro equipo al SERVER-A, lo pasaremos con scp al usuario "diego" con la ip del servidor: ```scp ./id_ed25519.pub diego@10.201.59.215:id_ed25519.diego.pub ```

Ahora desde el servidor tenemos que meter la clave publica en la carpeta ```.ssh/authorized_keys``` si no existe la creamos, para meter la clave dentro de la carpeta usaremos el comando cat, ```cat id_ed25519.diego.pub >> .ssh/authorized_keys```

Por ultimo deshabilitaremos el acceso SSH con contreseña, para ello editaremos el fichero ```/etc/ssh/sshd_config``` y donde ponga "PasswordAuthentication" pondremos "no"

Y ya nos podremos conectar de forma remota sin introducir credenciales a SERVER-A.

## Conexion a SERVER-B y SERVER-C

Lo primero sera configurar las redes internas, desde SERVER-A ejecutaremos ```ip link show``` para ver los nombres de los adaptadores, siendo enp0s8 la intnet 1 y enp0s9 la intnet 2, buscaremos el archivo de configutacion con ```ls /ect/netplan/``` se llamara ```01-netcfg.yaml``` o ```50-cloud-init.yaml``` lo editaremos ```sudo nano /etc/netplan/01-netcfg.yaml``` y le pondremos lo siguiente:

network:
  version: 2
  ethernets:
    enp0s9:
      addresses:
        - 10.20.0.1/16
    enp0s9:
      addresses:
        - 10.30.0.1/16

Y aplicaremos los cambios con ```sudo netplan apply```

El equipo SERVER-A tendra una ip 10.20.0.1 en la intnet 1 y una ip 10.30.0.1 en la intnet 2

Nos dirigiremos al SERVER-B y ejecutaremos el comando ```ip link show``` para ver el nombre del adaptador, siendo este enp0s8, buscaremos el archivo de configutacion con ```ls /ect/netplan/``` se llamara ```01-netcfg.yaml``` o ```50-cloud-init.yaml``` lo editaremos ```sudo nano /etc/netplan/01-netcfg.yaml``` y le pondremos lo siguiente:

network:
  version: 2
  ethernets:
    enp0s8:
      addresses:
        - 10.20.0.2/16

Y aplicaremos los cambios con ```sudo netplan apply```

El equipo SERVER-B tendra una ip 10.20.0.2 en la intnet 1

Nos dirigiremos al SERVER-C y ejecutaremos el comando ```ip link show``` para ver el nombre del adaptador, siendo este enp0s8, buscaremos el archivo de configutacion con ```ls /ect/netplan/``` se llamara ```01-netcfg.yaml``` o ```50-cloud-init.yaml``` lo editaremos ```sudo nano /etc/netplan/01-netcfg.yaml``` y le pondremos lo siguiente:

network:
  version: 2
  ethernets:
    enp0s8:
      addresses:
        - 10.30.0.2/16

Y aplicaremos los cambios con ```sudo netplan apply```

El equipo SERVER-C tendra una ip 10.30.0.2 en la intnet 2

Volveremos al SERVER-A y crearemos una clave publica con el comando ```ssh-keygen``` para poder conectarnos de forma transparente, añadiendole ```-b 1024``` le establecemos una longitud maxima.

Ahora, ejecutaremos ```cd ~/.ssh``` para dirigirnos a la carpeta ssh , tenemos que pasarle la clave publica del SERVER-A al SERVER-B y al SERVER-C, lo pasaremos con scp al usuario "sysadmin" con la ip del servidor: ```scp ./id_ed25519.pub sysadmin@10.20.0.2:id_ed25519.sysadmin.pub ``` y ```scp ./id_ed25519.pub sysadmin@10.30.0.2:id_ed25519.sysadmin.pub ```

Ahora desde los otros equipos tenemos que meter la clave publica en la carpeta ```.ssh/authorized_keys``` si no existe la creamos, para meter la clave dentro de la carpeta usaremos el comando cat, ```cat id_ed25519.sysadmin.pub >> .ssh/authorized_keys```

Por ultimo deshabilitaremos el acceso SSH con contreseña, para ello editaremos el fichero ```/etc/ssh/sshd_config``` y donde ponga "PasswordAuthentication" pondremos "no"

Y ya nos podremos conectar de forma remota sin introducir credenciales a SERVER-B y SERVER-C desde SERVER-A.

## Preguntas
1. **~/.ssh/id_rsa** contiene una cadena de texto cifrada o codificada que representa tu clave secreta. Actúa como tu llave física digital. Se queda siempre en tu máquina local. 
    **~/.ssh/id_rsa.pub** contiene una línea de texto plano que es matemáticamente el par del archivo anterior. Actúa como el "candado". Esta clave se comparte abiertamente y se copia en los servidores remotos a los que deseas acceder sin usar contraseña.

2. **~/.ssh/authorized_keys** contiene una lista de las claves públicas (.pub) de todos los usuarios o dispositivos que tienen permitido iniciar sesión en esa cuenta específica. Cada línea corresponde a una clave. Cuando intentas conectarte, el servidor consulta este archivo. Si tu clave privada local corresponde con alguna de las claves públicas listadas aquí, el servidor te permitirá el acceso de forma segura.

3. **~/.ssh/known_hosts** contiene las identidades criptográficas (huellas digitales o host keys) de todos los servidores remotos a los que te has conectado anteriormente. Evita ataques de suplantación de identidad (como el ataque Man-in-the-Middle). La primera vez que te conectas a un servidor, te pregunta si confías en él y guarda su clave aquí. En las siguientes conexiones, el cliente SSH verifica que la clave del servidor no haya cambiado; si cambia, el sistema bloqueará la conexión y te lanzará una alerta roja de seguridad.

4. **/etc/ssh/sshd_config** contiene las directivas de configuración globales para el demonio (servicio) del servidor SSH (sshd). Define las reglas de juego del servidor. Desde aquí puedes cambiar el puerto por defecto (el 22), deshabilitar el acceso al usuario root, desactivar la autenticación por contraseña para obligar a usar llaves SSH, o limitar qué usuarios del sistema operativo pueden conectarse.

5. **/var/log/auth.log** contiene el registro histórico de todos los intentos de autenticación y eventos de seguridad del sistema. Es una herramienta vital de auditoría. Si alguien intenta adivinar tu contraseña, si un usuario legítimo inicia sesión, o si un script automatizado falla al autenticarse, todo quedará registrado aquí con fecha, hora, dirección IP de origen y resultado del intento.

6. **/etc/hosts.allow** y **/etc/hosts/deny** contienen listas de control de acceso basadas en texto (utilizadas tradicionalmente por el mecanismo TCP Wrappers). Contienen pares de servicios y direcciones IP. Filtran qué IPs o rangos de red tienen permitido o denegado el acceso a servicios específicos antes de que la conexión sea procesada por el propio servidor SSH. 
   - **hosts.allow** define quién sí puede entrar.
   - **hosts.deny** define quién no puede entrar
